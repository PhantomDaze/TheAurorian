## 六、渲染层 / 剪裁双向差集（检查点 5）

### 6.1 机制取证

- NeoForge 21.1.248、Forge 47.4.10、Forge 43.4.6 的模型反序列化器均解析模型 JSON 的 `render_type`（universal jar 内字符串取证）。
- 模型未声明 `render_type` 时，`SimpleBakedModel.blockRenderTypes` 为 `null`，渲染类型回退到 `ItemBlockRenderTypes`。
- 对 `LeavesBlock`，`ItemBlockRenderTypes.getChunkRenderType` 在三个版本均有硬编码特判：`renderCutout ? CUTOUT_MIPPED : SOLID`。已用 `javap -c` 在 1.20.1 与 1.21.1 客户端类上复核。

### 6.2 双向差集结果

| 项目 | 1.21.1 | 1.20.1 | 1.19.2 |
|---|---:|---:|---:|
| 需要非 solid 层的方块 | 20 | 20 | 20 |
| 缺失渲染层 | 0 | 0 | 0 |
| 类型错配 | 0 | 0 | 0 |
| Java `setRenderLayer` 条数 | 11 | 11 | 2 |
| 与模型 `render_type` 重复 | 9 | 9 | 2 |
| 仅 Java、模型无 hint（两块玻璃） | 2 | 2 | 0 |
| 模型 `render_type` 声明数 | 51 | 51 | 57 |

- 上表 20 个为“按父族可判定”的非固体方块；另有 2 个满方块玻璃（`aurorian_glass`、`moon_glass`，仅 Java 注册）与 2 个树叶（`silentwood_leaves` 由 `LeavesBlock` 兜底、`weeping_willow_leaves` 显式 `cutout_mipped`）不在该判定集内，已逐项核对，均无缺层。
- 1.21.1/1.20.1 的 `EventsClient.java` 分别在第 63–73 行、56–66 行注册玻璃/玻璃板/火把/墙火把/梯子/高草/瓮；其中 9 条与模型 `render_type` 重复，2 条（`aurorian_glass`、`moon_glass`）用于父族无法判定的满方块玻璃。功能均正确。
- 1.19.2 只在第 58–59 行注册两个墙火把 cutout；其余非固体方块由模型 `render_type` 或 `LeavesBlock` 兜底覆盖。属迁移后的机制差异，不是缺层。
- 1.19.2 比新树多 6 条 `render_type`（`aurorian_glass`、`moon_glass`、`urn` 的 block/item 模型），与仅 2 条 Java 注册互补，渲染结果一致。
- **冗余项**：上述 Java 与模型重复的 9/9/2 条不影响渲染，属双保险；本轮未删除（删除会改变加载路径，收益为零、风险非零）。
- **误报核销**：`silentwood_leaves` 曾被 C/F 分支判为“缺 `cutout_mipped`”。对抗复核 2/3 证伪：该方块注册为原版 `LeavesBlock`（三树 `BlockRegistry` 均为 `new LeavesBlock(...)`），Fancy（默认）自动 `cutout_mipped`，Fast 下变 solid 与原版树叶完全一致；模型未写 `render_type` 不是缺陷。另 1 票“成立”的复核忽略了 `LeavesBlock` 兜底，不采信。
- 其他信息项：`moonlight_forge` 对全不透明贴图使用 `translucent`、`urn` 对全不透明贴图使用 `cutout`，均为无视觉收益的渲染层选择，非错误。

## 九、跨树一致性（检查点 8）

### 9.1 结构一致性

- 模型文件集合：三树均 427 个，文件名集合完全相同，无只在 1–2 棵树存在的模型。
- blockstate：三树均 107 个，文件名集合相同，且逐字节 md5 相同。
- 归一化（`forge:`/`neoforge:` → `<loader>:`、忽略 `render_type` 后按键排序）后，模型内容差异仅 2 项：
